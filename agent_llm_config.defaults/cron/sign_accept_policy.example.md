# Conditional accept sign request (policy template)

Bundled catalog job: **`conditional-accept-sign-request`** (default **disabled**). Copy the **`signAcceptPolicy`** YAML fence into the cron job **`message`**, customize for your node, then **Run now** once before enabling.

Load skill **`scheduled-automation`**. Purpose short codes: **`trade-defaults`** §4 (ctm1 format).

## Non-interactive rules

- Do **not** ask the operator questions or use MCP elicitation.
- Do **not** call `trigger_sign_result`, `broadcast_sign_result`, or create new `multiSignRequest` proposals.
- Process **one** pending Join request at a time (sequential).
- On **every** policy outcome call `sign_request_agree` — **`accept: true`** when all rules pass, **`accept: false`** when any rule fails (never leave failed policy rows pending without a reject vote).
- Always include the **complete Purpose string** (ctm1 codes + additional prose) and an **ISO 8601 UTC timestamp** in `thoughts`.

## Purpose evaluation (read first)

Sign requests store Purpose as a map: `{ "<originatorNodeKey128hex>": "<purpose text ≤256 chars>" }`.

1. Read the Purpose **value** for the originator key from `get_sign_request_by_id({ compact: false })`.
2. Split on middle dot **` · `** (space-dot-space):
   - **Before:** ctm1 structured prefix (if present)
   - **After:** additional prose (desk suffix, cron note, operator comment)
3. If no ctm1 prefix, treat the **entire** Purpose as additional prose; use MessageRaw / batchMeta fallback for chain/token/amount only when needed.

### ctm1 pipe format

```
ctm1|{proto}|{L|S}|{setup}|eE={px}|pfE={px}|...|sz={coinUnits}|szUsd={usdNotional}|{symShort} · {additional prose}
```

| Token | Policy use |
|-------|------------|
| `{proto}` | `hl`, `arc`, `gmx`, `uni` — protocol allow/block lists |
| `{L\|S}` | Side allow list |
| `{setup}` | Strategy code (`trend-ret`, `kl-bnc`, `kl-fib`, `bb-fade`, `dc-ret`, `dc-brk`, `zs-fade`, `fw-ret`, `ew-imp`, `ew-dia`, …) |
| `sz=` | Coin size (Hyperliquid / Arcus perp) — amount limits |
| `szUsd=` | USD notional (GMX / Uniswap) — amount limits |
| `{symShort}` | Trailing segment (e.g. `BTC`, `ETH`) — symbol allow list, live-position match |
| **Additional prose** | Keyword rules + agent interpretation per `purposeText` in YAML |

## Workflow (embed in cron message)

1. `list_sign_requests_awaiting_join` — filter rows with `localAgreementPending: true`.
2. If none, stop.
3. For each pending request (one at a time):
   - `get_sign_request_by_id({ requestId, compact: false })`
   - Resolve originator node key from `Purpose` map key or `originatorNodeKey` summary field
   - Split and parse Purpose (ctm1 + additional text)
   - Evaluate **`signAcceptPolicy`** YAML below against structured codes, additional prose, chain, tokens, amount limits, and optional live-position checks
   - If all enabled rules pass → `sign_request_agree({ requestId, accept: true, thoughts: "Sign request agreed automatically at <UTC>. Purpose: <full purpose>. All signAcceptPolicy conditions passed." })`
   - If any rule fails → `sign_request_agree({ requestId, accept: false, thoughts: "Sign request rejected automatically at <UTC>. Purpose: <full purpose>. Reason: <specific rule>." })`
4. Continue to next pending request; log errors but keep processing.

## signAcceptPolicy (YAML fence — paste into cron message)

Marker line `signAcceptPolicy:` then fenced YAML:

```yaml
version: 1

requireCtm1: true

originatorNodeKeys:
  - "04REPLACE_WITH_TRUSTED_ORIGINATOR_128_HEX"

purposeCodes:
  allowedProtocols: [hl, arc, gmx]
  blockedProtocols: []
  allowedSetups: [trend-ret, kl-bnc, kl-ret, kl-fib, bb-fade, dc-ret, dc-brk, zs-fade, fw-ret, ew-imp, ew-dia]
  blockedSetups: [kl-brk]
  allowedSymbols: [BTC, ETH]
  allowedSides: [L, S]

purposeText:
  blockedKeywords: [force, experimental, test-only, manual override]
  requiredKeywordsAny: []
  requiredKeywordsAll: []
  allowedKeywordsAny: [Generated by cron, trend retest, kl bounce, fib 618 fade, dc breakout, zs fade, ew wave]
  interpretationNotes: |
    Reject additional Purpose prose mentioning experimental sizing or manual override.
    Accept "Generated by cron" only when originator is in originatorNodeKeys.
    Desk suffixes: "fib 618 fade" (kl-fib), "dc breakout" (dc-ret/dc-brk), "zs fade" (zs-fade).

chains:
  chainIds: [42161, 999, 4663]

tokens: []

amountLimits:
  mode: per_request
  limits:
    - protocol: hl
      maxSzHuman: "0.5"
    - protocol: arc
      maxSzHuman: "0.5"
    - protocol: gmx
      maxSzUsdHuman: "10000"
    - symbol: BTC
      maxSzHuman: "1.0"

rejectIfLivePosition:
  enabled: true
  protocols: [gmx, hyperliquid, uniswap-v4, arcus]
  matchBy: same_market
```

**Optional sections:** omit or leave empty to allow-all for that dimension.

### amountLimits modes

| mode | Behavior |
|------|----------|
| **`per_request`** | Reject when proposed `sz=` / `szUsd=` (or decoded leg amount) exceeds limit |
| **`inclusive_with_live_positions`** | Reject when `existingExposure + proposed ≤ max` fails — fetch live positions first (`load_defi_protocol` + `ctm_*_fetch_positions`) |

### Live position checks (when `rejectIfLivePosition.enabled`)

| Protocol | Tool | Match |
|----------|------|-------|
| GMX | `ctm_gmx_fetch_positions` | `symbol` vs ctm1 `symShort` |
| Hyperliquid | `ctm_hyperliquid_fetch_positions` | `coin` vs `symShort` |
| Arcus | `ctm_arcus_fetch_positions` | market display name vs `symShort` |
| Uniswap V4 | `ctm_uniswap_v4_lp_list_positions` | registry-based; may miss unregistered NFTs |

Derive `executorAddress` from the sign request's `keyGenId` when fetch tools require it.

**Batch requests:** evaluate every leg; reject if **any** leg fails.

## Worked examples

### Example A — accept (originator + ctm1 + suffix OK)

Purpose: `ctm1|hl|L|trend-ret|eE=2950|pfE=2800|sz=0.5|BTC · trend retest`

- Originator in allowlist ✓
- `hl` allowed, `trend-ret` allowed, `BTC` allowed, `sz=0.5` ≤ 0.5 ✓
- Additional text passes keyword rules ✓
- **Accept** with thoughts citing full Purpose

### Example B — reject (size over limit)

Purpose: `ctm1|hl|L|trend-ret|eE=2950|sz=1.2|BTC · trend retest`

- `sz=1.2` > `maxSzHuman: "0.5"` for `hl` ✗
- **Reject:** `Reason: sz=1.2 exceeds maxSzHuman 0.5 for hl.`

### Example C — reject (blocked additional text)

Purpose: `ctm1|hl|L|fw-ret|sz=0.5|ETH · experimental sizing override`

- Blocked keyword `experimental` in additional prose ✗
- **Reject:** `Reason: blocked keyword "experimental" in additional Purpose text.`

### Example D — reject (live position conflict)

Purpose: `ctm1|hl|L|kl-bnc|sz=0.3|BTC · kl bounce`

- `ctm_hyperliquid_fetch_positions` shows open `BTC` long ✗ (when `rejectIfLivePosition.enabled`)
- **Reject:** `Reason: live Hyperliquid position on BTC conflicts with new long proposal.`

### Example E — inclusive_with_live_positions

Policy: `mode: inclusive_with_live_positions`, `maxSzHuman: "1.0"` for BTC on `hl`.

- Existing HL BTC long `sz=0.7`, new request `sz=0.5` → total 1.2 > 1.0 ✗
- **Reject:** `Reason: inclusive BTC exposure 1.2 exceeds max 1.0 (live 0.7 + proposed 0.5).`

### Example F — accept (Elliott wave cron)

Purpose: `ctm1|hl|L|ew-imp|eE=2950|pfE=2800|sz=0.5|BTC · ew wave · Generated by cron`

- `ew-imp` in `allowedSetups` ✓
- Additional suffix `ew wave` / `Generated by cron` passes keyword rules ✓
- **Accept** with thoughts citing full Purpose

## v1 limitations

- **Agent-evaluated only** — no mpc-auth parser for `signAcceptPolicy` in v1.
- Proposals without `ctm1|` are rejected when `requireCtm1: true`.
- Manual UI compose may use free-text Purpose until builders emit ctm1.
- Live-position checks count **filled** exposure, not resting orders.
